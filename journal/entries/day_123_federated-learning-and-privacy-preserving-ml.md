# Day 123 — Federated learning and privacy-preserving ML

## 🧠 Concept Explanation

Federated learning (FL) is a machine learning paradigm that trains a shared global model across many decentralized devices or servers holding local data samples, without exchanging the raw data. Each participant (client) computes a model update — typically the gradient or weight delta — on its own data and sends only this update to a central server. The server aggregates the updates (e.g., via weighted averaging, known as FedAvg) to produce a new global model, which is then broadcast back to the clients for the next round. This loop repeats until convergence. Because raw data never leaves the device, FL offers strong privacy guarantees, especially when combined with techniques such as differential privacy (adding calibrated noise to updates) and secure aggregation (cryptographic protocols that prevent the server from seeing individual updates). FL is particularly valuable in domains where data is sensitive (healthcare, finance) or bandwidth‑limited (mobile keyboards, IoT). However, it introduces challenges: non‑IID data distributions across clients, communication overhead, straggler devices, and potential model poisoning attacks. Researchers address these with personalized models, compression, robust aggregation, and incentive mechanisms.

---

## ✅ Key Points

- Data stays on local devices; only model updates are shared.
- Server aggregates updates (e.g., FedAvg) to form a global model.
- Privacy enhanced with differential privacy and secure aggregation.
- Challenges: non‑IID data, communication cost, stragglers, attacks.
- Applications: mobile keyboards, healthcare, finance, IoT.

## 💡 Real-World Analogy

Federated learning is like a group of doctors each learning from their own patients and only sharing the treatment insights — not the patient records — to improve a common medical guideline.

---

## ⚠️ Common Mistakes

- Assuming FL automatically guarantees privacy without adding differential privacy or secure aggregation.
- Ignoring data heterogeneity (non‑IID) and using a single global model for all clients.
- Neglecting communication efficiency, leading to impractical training on bandwidth‑limited devices.
