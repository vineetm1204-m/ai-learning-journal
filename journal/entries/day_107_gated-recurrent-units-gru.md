## 🧠 Concept Explanation

Gated Recurrent Units (GRU) are a streamlined variant of Long Short‑Term Memory (LSTM) networks designed to capture long‑range dependencies in sequential data while using fewer parameters. A GRU cell contains two gates: the update gate and the reset gate. The update gate decides how much of the previous hidden state should be carried forward, effectively combining the forget and input gates of an LSTM into a single mechanism. The reset gate controls how much of the past hidden state contributes to the candidate activation, allowing the model to forget irrelevant information. The candidate hidden state is computed from the current input and the reset‑gated previous hidden state. Finally, the new hidden state is a linear interpolation between the previous hidden state and the candidate, weighted by the update gate. Because GRUs lack a separate cell state, they are computationally cheaper and often train faster, yet they achieve comparable performance on many tasks such as language modeling, speech recognition, and time‑series forecasting. Their simplicity makes them a popular default choice when building recurrent architectures. In practice, GRUs often match LSTM accuracy with roughly 30% fewer parameters, making them attractive for deployment on memory‑constrained devices such as mobile phones or embedded systems. Researchers also explore variants like the minimal GRU and the light GRU to further reduce computation.

---

## ✅ Key Points

- GRU has two gates: update and reset, merging LSTM's three gates.
- Update gate controls how much previous hidden state is retained.
- Reset gate determines how much past information contributes to the candidate activation.
- No separate cell state; hidden state directly carries memory.
- Fewer parameters and faster training than LSTM with similar performance.

## 🏗️ Diagram / Formula

```
z_t = σ(W_z·[h_{t-1}, x_t])      # update gate
r_t = σ(W_r·[h_{t-1}, x_t])      # reset gate
ĥ_t = tanh(W·[r_t ⊙ h_{t-1}, x_t]) # candidate
h_t = (1 - z_t) ⊙ h_{t-1} + z_t ⊙ ĥ_t
```

---

## 💡 Real-World Analogy

A GRU works like a notebook where the update gate decides whether to overwrite a page, and the reset gate decides whether to erase old notes before writing new ones.

---

## ⚠️ Common Mistakes

- Confusing the update gate with LSTM's separate forget and input gates.
- Forgetting that the reset gate multiplies the previous hidden state before the candidate computation.
- Assuming GRU always outperforms LSTM; in some tasks LSTM's extra capacity helps.
