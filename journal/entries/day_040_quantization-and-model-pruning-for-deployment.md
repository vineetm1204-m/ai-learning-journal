# Day 40 — Quantization and model pruning for deployment

## 🧠 Concept Explanation

Quantization and pruning are two complementary techniques that shrink neural networks for fast, memory‑efficient inference on edge devices. Quantization reduces the numerical precision of weights and activations — typically from 32‑bit floating point to 8‑bit integers — by mapping a continuous range onto a discrete set of levels. This can be done post‑training (static quantization) using a calibration dataset to choose scale and zero‑point parameters, or quantization‑aware training (QAT) where fake‑quantization nodes are inserted during training so the model learns to be robust to precision loss. Pruning, on the other hand, removes unnecessary parameters. Structured pruning deletes entire filters, channels, or layers, preserving dense matrix multiplications and enabling direct speed‑ups on hardware. Unstructured pruning zeros out individual weights, yielding higher compression but requiring sparse‑matrix kernels for real gains. Both methods can be combined: a model is first pruned to reduce the parameter count, then quantized to lower the bit‑width. The trade‑off is accuracy versus latency; careful calibration, fine‑tuning, and hardware‑aware scheduling are essential to keep the degradation within acceptable bounds while achieving 2‑4× speed‑up and 4‑8× memory reduction.

---

## ✅ Key Points

- Quantization maps FP32 values to INT8 using scale and zero‑point, enabling integer arithmetic.
- Post‑training quantization is fast but may hurt accuracy; quantization‑aware training mitigates this.
- Structured pruning removes whole filters/channels, preserving dense compute; unstructured pruning zeros individual weights.
- Combining pruning then quantization yields multiplicative compression and latency benefits.
- Hardware support (e.g., TensorRT, TFLite, ONNX Runtime) dictates which quantization/pruning scheme is practical.

## 💡 Real-World Analogy

Quantization is like rounding prices to the nearest dollar for faster mental math, while pruning is like removing rarely used tools from a toolbox so it’s lighter and quicker to find what you need.

---

## ⚠️ Common Mistakes

- Applying post‑training quantization without a representative calibration set, causing large accuracy drops.
- Pruning aggressively without fine‑tuning, leaving the model unable to recover lost capacity.
- Ignoring hardware constraints (e.g., lack of INT8 kernels) and expecting speed‑ups that never materialize.
