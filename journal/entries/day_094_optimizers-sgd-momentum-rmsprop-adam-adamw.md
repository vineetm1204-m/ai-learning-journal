# Day 94 — Optimizers: SGD, Momentum, RMSProp, Adam, AdamW

## 🧠 Concept Explanation

Optimizers navigate the loss landscape to find parameters that minimize error. Stochastic Gradient Descent (SGD) takes steps proportional to the negative gradient, but its fixed learning rate causes oscillations in ravines and slow progress on plateaus. Momentum adds a velocity term that accumulates past gradients, smoothing the path and accelerating through flat regions while dampening oscillations. RMSProp adapts the learning rate per parameter by dividing by a running average of recent gradient magnitudes, effectively normalizing updates — large gradients get smaller steps, small gradients get larger ones. Adam combines Momentum's velocity with RMSProp's adaptive scaling, computing bias-corrected estimates of both first and second moments. It became the default choice for deep learning due to fast convergence and robustness. AdamW improves on Adam by decoupling weight decay from the adaptive learning rate: instead of adding L2 regularization to the gradient (which interacts poorly with adaptive scaling), it applies weight decay directly to the parameters after the adaptive step. This fixes Adam's generalization gap, especially for transformers and large models. Choosing an optimizer involves trade-offs: SGD with momentum often generalizes better with careful tuning; Adam/AdamW converge faster out-of-the-box. Learning rate scheduling, warmup, and gradient clipping are complementary practices that significantly impact final performance.

## ✅ Key Points

- SGD updates parameters using fixed learning rate × gradient; simple but struggles with ill-conditioned loss landscapes
- Momentum accumulates exponentially weighted average of past gradients to accelerate convergence and reduce oscillation
- RMSProp adapts per-parameter learning rates using moving average of squared gradients, normalizing update magnitudes
- Adam combines Momentum (first moment) and RMSProp (second moment) with bias correction for fast, robust convergence
- AdamW decouples weight decay from adaptive learning rates, improving generalization over Adam, especially for transformers

## 🏗️ Diagram / Formula

```
SGD:        θ ← θ - η·g
Momentum:   v ← β·v + (1-β)·g;  θ ← θ - η·v
RMSProp:    s ← γ·s + (1-γ)·g²;   θ ← θ - η·g / √(s + ε)
Adam:       m ← β₁·m + (1-β₁)·g;  v ← β₂·v + (1-β₂)·g²
            m̂ ← m/(1-β₁ᵗ);       v̂ ← v/(1-β₂ᵗ)
            θ ← θ - η·m̂ / (√v̂ + ε)
AdamW:      θ ← θ - η·(m̂/(√v̂+ε) + λ·θ)  // weight decay applied directly to θ
```

## 💡 Real-World Analogy

SGD is like hiking downhill in fog with fixed step size; Momentum adds a heavy ball that rolls through small bumps; RMSProp adjusts step size per terrain steepness; Adam combines both with a compass; AdamW ensures the backpack weight (regularization) doesn't distort the compass reading.

---

## ⚠️ Common Mistakes

- Using Adam's default weight decay (L2 on gradients) instead of AdamW's decoupled weight decay, hurting generalization on transformers
- Setting learning rate too high for adaptive methods, causing divergence despite per-parameter scaling
- Skipping learning rate warmup for large models with Adam/AdamW, leading to unstable early training
