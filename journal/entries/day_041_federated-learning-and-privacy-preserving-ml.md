# Day 41 — Federated learning and privacy-preserving ML

## 🧠 Concept Explanation

Federated learning flips the traditional data‑center paradigm: instead of gathering raw data on a central server, the model travels to where the data lives — on phones, edge devices, or siloed institutions. Each client computes a local update (usually a few SGD steps) on its private dataset and sends only the model delta (or encrypted gradients) back. The server aggregates these updates, commonly via weighted averaging (FedAvg), to produce a new global model that is then redistributed. Because raw samples never leave the device, privacy exposure is dramatically reduced, though inference attacks on the shared updates remain a concern. Techniques such as secure aggregation, differential privacy, and homomorphic encryption further harden the protocol. Communication efficiency is critical; methods like model compression, sparsification, and adaptive client selection mitigate bandwidth constraints. Federated learning also naturally handles non‑IID data distributions, but this heterogeneity can slow convergence and bias the global model toward majority clients. The approach enables collaborative AI across hospitals, banks, and mobile keyboards while respecting regulations like GDPR and HIPAA.

---

## ✅ Key Points

- Training occurs locally on client devices; only model updates are shared.
- Server aggregates updates (e.g., FedAvg) to form a global model.
- Privacy is enhanced by keeping raw data on‑device and using secure aggregation or DP.
- Communication overhead is a major bottleneck; compression and client sampling help.
- Non‑IID data across clients challenges convergence and fairness.

## 💡 Real-World Analogy

Imagine a group of chefs each perfecting a secret sauce in their own kitchen; they only share the recipe adjustments, not the ingredients, and a head chef blends the tweaks into a master recipe sent back to all.

---

## ⚠️ Common Mistakes

- Assuming federated learning alone guarantees privacy — without secure aggregation or DP, updates can leak data.
- Ignoring data heterogeneity, leading to biased global models that underperform for minority clients.
- Overlooking communication costs, causing impractical training times on bandwidth‑limited devices.
