# Day 82 — Federated learning and privacy-preserving ML

## 🧠 Concept Explanation

Federated learning enables many devices to collaboratively train a shared model without ever sending raw data to a central server. Each client downloads the current global model, computes a local update using its own private dataset, and sends only the model delta—typically gradients or weight changes—back to the server. The server aggregates these updates, often by weighted averaging, to produce a new global model that reflects knowledge from all participants. Because data never leaves the device, privacy risks are dramatically reduced, and communication overhead can be managed by compressing updates or selecting a subset of clients each round. Extensions such as secure aggregation, differential privacy, and homomorphic encryption further protect against inference attacks on the transmitted updates. The approach is especially valuable for mobile keyboards, health monitoring, and any scenario where data is sensitive, regulated, or simply too large to centralize. However, challenges remain: statistical heterogeneity across clients can slow convergence, stragglers and device drop‑out require robust aggregation, and the system must balance model accuracy with communication and privacy budgets.

---

## ✅ Key Points

- Data stays on device; only model updates are exchanged.
- Server aggregates updates via weighted averaging (FedAvg) or secure aggregation.
- Privacy enhancements: differential privacy, secure multiparty computation, homomorphic encryption.
- Challenges include non‑IID data, client dropout, and communication efficiency.
- Typical use‑cases: on‑device keyboard prediction, medical imaging across hospitals, IoT sensor networks.

## 💡 Real-World Analogy

Think of a study group where each student solves practice problems at home and only shares their answer corrections with the tutor, who then creates a master solution without ever seeing anyone's raw notes.

---

## ⚠️ Common Mistakes

- Assuming federated learning automatically guarantees privacy; without extra mechanisms (DP, secure aggregation) updates can leak data.
- Ignoring data heterogeneity and using a single global learning rate, which often leads to poor convergence.
- Neglecting communication constraints—sending full model weights each round can be prohibitive on mobile networks.
