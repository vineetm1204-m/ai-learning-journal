## 🧠 Concept Explanation

Gradient descent is the workhorse optimization algorithm that iteratively adjusts model parameters to minimize a loss function. The three main variants differ in how much data they use to compute the gradient at each step. Batch gradient descent uses the entire training set, yielding a precise but computationally expensive gradient estimate. Stochastic gradient descent (SGD) uses a single randomly chosen example per update, introducing high variance but enabling frequent updates and escape from shallow local minima. Mini-batch gradient descent strikes a balance: it computes the gradient on a small subset (typically 32-512 samples), reducing variance compared to SGD while leveraging vectorized hardware for efficiency. The trade-off centers on gradient estimate quality versus update frequency and hardware utilization. Batch GD converges smoothly but slowly per epoch; SGD converges noisily but can make progress after seeing few samples; mini-batch offers a practical sweet spot. Learning rate schedules, momentum, and adaptive methods (Adam, RMSprop) further refine these dynamics. Choosing batch size affects generalization: smaller batches often find flatter minima that generalize better, while very large batches may converge to sharp minima. Modern practice defaults to mini-batch with adaptive optimizers, tuning batch size as a hyperparameter.

---

## ✅ Key Points

- Batch GD uses all data per step: low variance, high compute per update.
- SGD uses one sample per step: high variance, frequent updates, good for online learning.
- Mini-batch (32-512) balances variance reduction and hardware parallelism.
- Smaller batches often generalize better due to noise-induced exploration.
- Adaptive optimizers (Adam) reduce sensitivity to learning rate across batch sizes.

## 🏗️ Diagram / Formula

```
θ_{t+1} = θ_t - η * ∇_θ L(θ_t)

Batch:      ∇L = (1/N) Σ ∇ℓ_i
SGD:        ∇L = ∇ℓ_i          (i random)
Mini-batch: ∇L = (1/B) Σ_{i∈batch} ∇ℓ_i
```

## 💡 Real-World Analogy

Like hiking down a foggy mountain: batch GD surveys the whole slope before each step (slow but steady), SGD peeks at one random rock (fast but jittery), mini-batch checks a small patch ahead (practical compromise).

---

## ⚠️ Common Mistakes

- Using batch GD on large datasets, causing memory overflow and slow iterations.
- Setting batch size too large (e.g., full dataset) and losing generalization benefits of noise.
- Forgetting to scale learning rate when changing batch size (linear scaling rule).
